  <action>
Create `public/icons/` directory and generate two PNG icons using an inline Node.js script. The icon design is a simple blue circle (#3B82F6) with white text "PI" centered — a clean, recognizable placeholder that satisfies the PWA icon requirement.

Run this Node.js script (no external dependencies — uses only built-in `fs` and `Buffer`):

```bash
node -e "
const fs = require('fs');
fs.mkdirSync('public/icons', { recursive: true });

// Minimal valid PNG generator (pure Node, no canvas needed)
// Creates solid blue squares with correct PNG binary structure
function createPNG(size) {
  // We'll write a minimal SVG and note: since we can't use canvas without installing,
  // create a simple solid-color PNG using raw bytes
  // Actually: write SVG files that vite-plugin-pwa can use — rename to .png
  // BUT manifest requires .png — so write minimal 1x1 scaled PNG
  // Best approach: copy the existing SVG as PNG-named files won't work.
  // Instead output a minimal valid PNG (solid blue 192x192).
  // PNG signature + IHDR + IDAT + IEND
  const PNG_SIG = Buffer.from([137,80,78,71,13,10,26,10]);
  function chunk(type, data) {
    const t = Buffer.from(type);
    const len = Buffer.alloc(4); len.writeUInt32BE(data.length);
    const crc = crc32(Buffer.concat([t, data]));
    const c = Buffer.alloc(4); c.writeUInt32BE(crc >>> 0);
    return Buffer.concat([len, t, data, c]);
  }
  function crc32(buf) {
    let c = 0xFFFFFFFF;
    for (const b of buf) { c ^= b; for (let i=0;i<8;i++) c = (c>>>1)^(c&1?0xEDB88320:0); }
    return (c^0xFFFFFFFF);
  }
  const IHDR = chunk('IHDR', (() => { const b=Buffer.alloc(13); b.writeUInt32BE(size,0); b.writeUInt32BE(size,4); b[8]=8; b[9]=2; return b; })());
  // Raw image data: each row = filter byte 0 + RGB pixels
  const row = Buffer.alloc(1 + size*3);
  row[0]=0; // filter none
  for(let x=0;x<size;x++) { row[1+x*3]=0x3B; row[2+x*3]=0x82; row[3+x*3]=0xF6; } // #3B82F6
  const raw = Buffer.concat(Array(size).fill(row));
  const zlib = require('zlib');
  const compressed = zlib.deflateSync(raw);
  const IDAT = chunk('IDAT', compressed);
  const IEND = chunk('IEND', Buffer.alloc(0));
  return Buffer.concat([PNG_SIG, IHDR, IDAT, IEND]);
}
fs.writeFileSync('public/icons/icon-192.png', createPNG(192));
fs.writeFileSync('public/icons/icon-512.png', createPNG(512));
console.log('Icons written: 192x192 and 512x512 solid blue PNG');
"
```

This produces valid PNG files (solid #3B82F6 blue) that satisfy the PWA icon requirement. They render as a recognizable brand color on home screens and in install prompts. No external package needed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser cache → app | Service worker intercepts fetch; only serves files it cached at install time |
| User device → IndexedDB | All assessment data stays on-device; no network egress |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Service worker cache | accept | App is served from a trusted origin (GitHub Pages or localhost); no user-supplied content enters the cache; cache is populated only from the build output |
| T-03-02 | Information Disclosure | IndexedDB assessment data | accept | Data never leaves the device; no API calls, no cloud sync; browser sandboxing prevents cross-origin access |
| T-03-03 | Denial of Service | Service worker update loop | mitigate | Use `registerType: 'autoUpdate'` + `cleanupOutdatedCaches: true` to evict stale caches on update; avoids stuck workers serving old assets |
| T-03-04 | Spoofing | Web app manifest | accept | Manifest is bundled at build time from controlled source; no runtime manifest fetching from untrusted sources |
</threat_model>
